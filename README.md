# PricePulse

Telegram Mini App и Railway-бот для мониторинга цен.

## Что уже работает

- каталог товаров и фильтрация по категориям;
- избранное, поиск и пользовательские подборки;
- добавление товара по ссылке;
- интервалы мониторинга от 1 часа и собственный период;
- карточка товара с историей и прогнозом цены;
- сравнение предложений магазинов;
- собственные цветовые темы;
- постоянная D1-память товаров, избранного, палитры и подборок;
- отдельные профили с безопасным входом через Telegram Mini App без Gmail;
- локальная копия данных как резерв при временной потере связи;
- опциональный OpenRouter-провайдер для AI-подборок;
- адаптация под мобильный Telegram WebView;
- Telegram-команды `/start`, `/app` и `/help`;
- кнопка запуска Mini App из сообщения бота;
- Railway worker с long polling и автоматическим перезапуском.

## Локальный запуск интерфейса

```bash
npm install
npm run dev
```

Проверка проекта: `npm test`.

## Запуск Telegram-бота на Railway

Railway использует `railway.toml` и автоматически запускает `npm run bot`.

Добавьте в Railway → Variables:

```env
BOT_TOKEN=<токен из BotFather>
WEBAPP_URL=https://pricepulse-app.bokcerkbr.chatgpt.site
BOT_POLLING_TIMEOUT=30
```

Для облачных профилей в настройках Sites добавьте только публичный числовой `TELEGRAM_BOT_ID` — это цифры до двоеточия в токене BotFather. Сам токен передавать в интерфейс не нужно.

OpenRouter включается автоматически после добавления серверных переменных:

```env
OPENROUTER_API_KEY=<ключ OpenRouter>
OPENROUTER_MODEL=openrouter/auto
```

Не коммитьте настоящий `BOT_TOKEN` и не отправляйте его в чат. После добавления переменных выполните Redeploy. Успешный запуск подтверждается строкой:

```text
[bot] @price_pulce_bot connected
```

Если Railway следит за веткой `main`, сначала объедините рабочий PR с `main` либо переключите Source Branch на `codex/ideas-themes`.

## Память и безопасность

Профиль определяется по подписанному Telegram `initData`, которое проверяется на сервере. Telegram ID из браузера не считается доверенным без подписи. Данные разных пользователей хранятся раздельно в D1 и переживают перезапуски Railway и повторные публикации интерфейса.

Ключи BotFather и OpenRouter должны оставаться только в переменных окружения и никогда не отправляться в клиентский код.
